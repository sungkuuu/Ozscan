## 1. 검증 질문 (주가설 하나만)

**"Ozscan 스마트머니의 매수 신호를 '실제 감지 시점'에 따라갔을 때, 1시간 후 가격 변화가 수수료+보수적 체결비용 차감 후에도 양수인가?"**
- 1차 지표: 비용 차감 1시간 forward markout / 보조: 5분·30분·24시간 / 별도: resolution 수익
- 1차 분석은 BUY만 (SELL·부분청산·반대포지션은 후속)

## 2. 분석 단위 — signal episode

동일 (지갑, asset_id, 방향, 5분 이내 체결)을 1 에피소드로 병합.
**추가 요건: BUY/SELL로 순포지션을 재구성해 실제 익스포저가 증가한 '진입 에피소드'만 신호로 인정** — 5분 묶음만으로는 마켓메이커 왕복 체결이 신호로 섞임.
기록: 총매수액, VWAP 진입가, 첫 체결 시각, **감지 시각(created_at)**, 감지지연, 감지시점 시장가, +5m/+30m/+1h/+24h 가격.

제외 필터: 가격 <5¢ 또는 >95¢ / $100 미만 진입 / timestamp 오염 / 감지지연 >5분 / 기존 대형 포지션의 단순 추가매수 / 측정시점 전 종료 시장 / 양방향 고빈도(MM 의심) 지갑.

## 3. 데이터 복원 (백테스트 전 필수)

**trade_id별 개별 재조회 금지 (67만 콜).** 공식 `/trades` API의 필터(지갑, 시장, 시작·종료 시각, BUY/SELL)를 사용해 **42개 지갑 × 일 단위 구간으로 BUY·SELL 각각 배치 조회** 후 transaction hash로 로컬 매칭. ([공식 Trades API](https://docs.polymarket.com/api-reference/core/get-trades-for-a-user-or-markets))

복원 테이블 스키마:
```
transaction_hash, wallet, condition_id, asset_id,
outcome(YES/NO), action(BUY/SELL), trade_time,
observed_at(②실시간 윈도우 행만), price, size
```
추가 복원 항목: 카테고리, 종료시각, 수수료 유형, resolution.

## 4. 가격 기준

- odds_snapshots는 결과토큰 미상 → 기준가로 직접 쓰지 않음. condition_id→YES/NO asset_id 매핑 후 **공식 prices-history API(1분 fidelity)로 토큰별 가격 확보**, 기존 5분 스냅샷과 대조(차이 큰 마켓 제외).
- **copy_price = 감지 시각 이후 처음 관찰되는 해당 토큰 가격** (리더 체결가 금지 — 알림 지연으로 소멸한 엣지 제거).

## 5. 산식

```
gross_markout(h) = token_price(t+h) − copy_price   # 센트 단위 (ROI 아님)
net_markout = gross − taker fee(진입+청산) − adverse execution
비용 시나리오: 낙관 왕복 1¢ / 기준 왕복 2¢ / 보수 왕복 4¢ (+공식 수수료 공식 별도 적용)
```
BUY YES: 미래YES−진입 / SELL YES: 진입−미래YES / BUY NO·SELL NO 대칭.
